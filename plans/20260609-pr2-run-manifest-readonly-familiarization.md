# ExecPlan: Lab Run Manifest and Read-only Target Familiarization Pack

## Purpose / Big Picture

PR2 makes adc-lab read-only target familiarization self-contained, auditable, reproducible, and claim-boundary aware.

The goal is to let a Pi5 controller run read-only inventory, toolchain discovery, and passive observation against a Pi4 target, then preserve the result as a Lab Run Manifest, Familiarization Pack, audit log, and claim evidence trace. This phase does not add privileged control, cpufreq writes, load generation, or destructive experiments.

## Scope

In scope:
- `lab.run_manifest.v1` schema, golden fixture, and Rust model.
- Expanded `lab.familiarization_pack.v1` schema and model for observational read-only status, supported claims, blocked claims, and next evidence.
- Artifact references using `artifact://lab/runs/<run_id>/...` in Agent-facing run summary fields.
- Read-only familiarization command or script that runs inventory, toolchain discover, observe, and report pack into one run directory.
- Audit completeness check for the read-only familiarization run.
- Claim evidence trace for observed-only familiarization.
- Documentation for Pi5 controller to Pi4 target read-only smoke.

Out of scope:
- `sudo` helper apply.
- cpufreq governor writes or fixed-frequency sweep.
- CPU, memory, I/O, thermal, GPU, or NPU load generation.
- Systemd/Unix-socket root helper.
- Production NFR budget claims.

## Constraints / Quality Targets

- Default `make verify` remains hardware-free.
- PR2 must not add any privileged apply, root helper transport, cpufreq write, or load path.
- All new schemas use strict minimal skeleton style: `required`, `enum` where useful, and `additionalProperties: false`.
- Claim output must distinguish read-only observation from controlled operating point evidence.
- Audit output must make missing inventory/toolchain/observe/report events visible.
- No raw local filesystem paths in Agent-facing artifact reference fields.

## Context & Orientation

Key existing files:
- `crates/adc-lab-core/src/run.rs`: run directory creation and artifact URI resolver.
- `crates/adc-lab-core/src/report.rs`: familiarization pack and report helpers.
- `crates/adc-lab-core/src/contracts.rs`: serde DTOs for schemas.
- `crates/adc-lab/src/main.rs`: CLI commands and audit writes.
- `schemas/` and `tests/golden/`: contract fixtures checked by `make contract`.
- `crates/adc-lab/tests/cli.rs`: CLI integration coverage.

Existing behavior:
- `inventory`, `toolchain discover`, and `observe` each write artifacts and append audit events.
- `report pack` writes a minimal familiarization pack and collects logical artifact refs.
- `experiment run` is still dry-run/planning only for real execution claims.

Unknowns to resolve during implementation:
- Whether to implement `adc-lab familiarize read-only` directly or provide only a script. Preference: direct CLI if it stays small and reuses existing functions.
- Whether run manifest is written incrementally by every command or generated by report pack. Preference: generate/update during report pack and read-only familiarization so PR2 stays scoped.

## Design

Data model:
- Add `RunManifest`, `RunArtifactRef`, and `RunDataQuality` DTOs.
- Expand `FamiliarizationPack` to include `pack_status`, `supported_claims`, `blocked_claims`, and `next_evidence_needed`.
- Keep existing fields such as `artifact_refs`, `audit_event_count`, `restore_status`, and `claim_trace_ref` for compatibility with PR1 report behavior.

Read-only familiarization flow:
- New command: `adc-lab familiarize read-only --target <target> --duration <duration> [--sample-interval <duration>] [--signals ...] [--run-dir ...]`.
- It creates/opens one run directory.
- It collects inventory, toolchain inventory, passive observation.
- It writes a read-only claim trace.
- It writes `run_manifest.json` and `reports/familiarization_pack.json`.
- It emits audit events for inventory, toolchain, observe, claim trace, run manifest, and familiarization pack.

Artifact refs:
- Manifest and pack fields use logical `artifact://lab/runs/...` refs.
- CLI wrapper may keep `artifact_path` for local usability, but value objects must not encode raw local paths as evidence refs.

Audit completeness:
- Add a helper that reads `audit.jsonl` and reports required read-only operations as present/missing.
- Manifest `data_quality.missing` includes missing audit operations and explicit missing evidence such as controlled operating point experiments not run.

Observability:
- Existing audit log is the diagnostic signal for read-only familiarization.
- PR2 adds operation-level audit events for report generation so operators can see whether pack/manifest creation happened.
- No secrets/PII should be logged; target strings are existing user-supplied target aliases.

Test strategy:
- Contract fixture validation for `lab.run_manifest.v1` and expanded `lab.familiarization_pack.v1`.
- Unit tests for manifest/pack generation and artifact refs.
- CLI test for `familiarize read-only` local run with short duration.
- CLI test that pack/manifest claim boundary blocks controlled/load/production claims.
